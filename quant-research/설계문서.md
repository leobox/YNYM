## 1. 사용자가 원하는 것

### 1.1 최종 목표

**안정적으로 우상향하는 종목을 찾아, 과도하게 오른 가격을 뒤쫓지 않고 진입하여 약 +10% 수익을 얻고 나오는 것을 돕는 도구.**

- 사용자가 종목을 직접 광범위하게 검색하는 부담을 줄인다.
- 애매한 종목을 억지로 추천하지 않는다. 조건이 없으면 0개가 정상이다.
- 신호를 기다리고 정해진 후보만 검토하여 충동 매매를 줄인다.
- 오랫동안 횡보하는 종목에 자금이 묶이는 기회비용도 고려한다.
- 높은 승률뿐 아니라 평균 수익, 계좌 잔고, 최대 낙폭, 보유 기간을 함께 본다.
- 사용자는 한때 95% 도달률을 희망했으나, **95%가 검증되거나 보장된 상태는 아니다.** 이 숫자에 맞추기 위한 과최적화는 금지한다.

| 관찰표 | 기본 패턴·돌파·거래대금이 모두 통과하여 다음 봉 마감 확인만 남은 종목 |

### 1.3 사용자에게 중요한 표현

- ‘패턴 충족’은 ‘지금 사도 유리함’과 다르다.
- ‘관찰’은 매수 신호가 아니다.
- 돌파선은 추천 매수가가 아니다.
- 확정되지 않은 봉은 **다음 봉 마감 대기**라고 표시한다.
- 정보는 충분히 제공하되 불필요하게 판단을 대신하거나 기능을 무겁게 만들지 않는다.
- 기본 패턴 미충족 종목, 거래대금 부족 종목 등을 관찰표에 섞지 않는다.

주의: 코드 끝자리·종목명 규칙은 정확한 보통주 분류를 보장하는 공식 분류 체계가 아니다. 새 프로젝트에서 검증해야 한다.

### 4.2 실제 사용 중인 주소

- 종목 목록: `https://m.stock.naver.com/api/stocks/marketValue/{KOSPI|KOSDAQ}?page=N&pageSize=100`
- 시간봉: `https://query1.finance.yahoo.com/v8/finance/chart/{종목코드}.KS` 또는 `.KQ`
- 후보 현재가: `https://m.stock.naver.com/api/stock/{종목코드}/basic`
- 후보 당일 정보: `https://m.stock.naver.com/api/stock/{종목코드}/integration`

네이버 주소는 공개 웹페이지에서 사용하는 비공식 엔드포인트다. 영구 제공·무제한 호출·항상 무지연을 보장하지 않는다. `integration`이라는 URL 이름만으로 KRX/NXT 통합 시세라고 단정하지 않는다.

현재가 추가 조회는 화면에 남은 종목 코드를 중복 제거한 후 실행한다. 후보당 basic·integration 각 1회이며 실패 재시도가 발생할 수 있다. 무한 폴링은 하지 않는다. 후보가 없으면 추가 현재가 조회도 없다.

### 4.3 봉 처리

- 모든 시각은 Asia/Seoul로 변환.
- 시·분·초가 정규 봉 시작에 맞는 데이터만 사용.
- 중복 인덱스·미완료봉 제거.
- 장 종료 후 야후가 추가하는 **거래량 0·고가=저가인 15시 표시용 봉**은 제외.
- OHLC 가격 정합성, 음수 거래량, 비정상 숫자 검사.
- 실시간 스캐너는 최소 120개 봉 필요.
- 최근 7일 이내 데이터인지 검사하지만, **이것만으로 장중 최신성까지 보장되지는 않는다.**

### 4.4 확인된 데이터 한계

1. 확보한 과거 데이터는 주로 09~14시 시작 봉이며 **15:00~15:30 구간이 빠져 있다.**
2. 시간봉 시작 14시는 14~15시 구간이다. 그 종가는 공식 15:30 종가가 아니다.
3. 야후 과거 값은 조회 시점에 따라 바뀔 수 있으므로 원본 동결·조회 시각 기록이 필요하다.
4. 네이버 현재가 한 번으로 다음 봉의 장중 저가나 마감가를 복원할 수 없다.
5. 야후와 네이버의 수정주가·거래시장 기준 일치 여부가 완전히 검증되지 않았다.
6. 초기 대화에서 언급된 ‘네이버 실시간 KRX 60분봉으로 전환’은 **현재 구현 상태가 아니다.** 현재 패턴 계산은 야후 60분봉이다.

## 5. 현재 운영 전략의 정확한 정의

### 5.1 기본 패턴

`hourly_pattern()`을 사용한다. SMA12, SMA26, rolling14 ATR을 이용한다.

- 12선의 최근 3봉 기울기 > 0.
- 26선의 최근 3봉 기울기가 3봉 전보다 개선.
- 종가 > 12선, 종가 > 26선.
- 최근 3봉 분당 거래량 평균 / 그 이전 20봉 분당 거래량 평균 ≥ 1.
- 직전 20봉 중 12선이 26선 아래인 시점 존재.
- 가격 ≥ 2,000원, 점수 유한값.

점수는 근접도·방향·거래량·과열 정도·수렴 또는 박스 돌파를 합성한다. 거래량 점수 기본 비중 20%. 재반등과 수렴돌파 점수 중 큰 값을 사용한다. **점수는 상승 확률이 아니다.** 정확한 계산은 소스가 기준이다.

### 5.2 돌파봉 조건

- 12·26선이 각각 3봉 전보다 높음.
- 종가가 두 이평선 위.
- 종가가 **직전 6봉 고가의 최댓값**을 초과.
- 양봉이며, `(종가-저가)/(고가-저가) ≥ 0.7`.
- `(종가-SMA26)/ATR ≤ 4`.
- 추정 거래대금 `종가×거래량 ≥ 10억원`.
- 과거 같은 시간대 최대 20개 봉의 거래대금 중앙값 대비 ≥ 2배. 과거 표본 최소 5개, 현재 봉은 기준값 계산에서 제외.

추정 거래대금은 체결 가격×수량의 실제 합계와 다르다. 단순 주식 수 ‘100만 주’ 조건은 사용하지 않는다.

### 5.3 다음 봉 유지 조건

돌파봉 바로 다음 완료봉에서:

- 저가 ≥ 돌파선.
- 종가 ≥ 돌파봉 종가.
- 12·26선 상승 및 가격이 두 선 위.
- 26선 이격 ≤ 4 ATR.
- 확인 시점에도 기존 기본 패턴 충족.

중간에 돌파선 아래로 내려갔다가 회복해도 다음 봉의 저가 조건은 탈락한다. 다음 봉에서 거래대금이 다시 2배가 될 필요는 없다.

### 5.4 최종 표와 관찰표

- 최종 표: 위 조건을 모두 통과한 종목, 점수 내림차순·코드 오름차순, 최대 5개.
- 관찰표: **현재 완료봉에서 기본 패턴·돌파·거래대금까지 통과했으며 다음 봉 마감만 기다리는 종목.** 현재 구현은 관찰표에 별도 5개 제한을 두지 않는다.
- 기본 패턴 미충족, 단순 직전봉 돌파, 대금 미충족만 있는 종목은 관찰표에 표시하지 않는다.
- 최종 표의 종목을 관찰표에 중복 표시하지 않는다.
- 현재가 추가 조회는 후보 자격·순위를 바꾸지 않는다.
- 자동 주문, 자동 매도, 검증된 추천 매수가 산출 기능은 없다.

### 5.5 시각 예시

```text
09:00~10:00 돌파봉 완료
10:00~11:00 다음 봉 진행
11:00 이후 다음 봉 마감 데이터 도착 → 최종 패턴 판단
```

10:47 네이버 현재가가 돌파봉 종가 위여도, 10~11시 봉 저가와 11시 종가가 확인된 것은 아니다. 기존 백테스트의 지연 없는 진입은 확인봉 뒤 **11시 시작 봉 시가**였으며, 실제 조회에 30~60초가 걸린 뒤의 체결 가격과 같지 않다.

## 6. 모바일 화면 요구사항

현재 화면은 가로 스크롤을 줄인 종목별 2열 표다.

- 어두운 배경, 큰 현재가, 종목명·코드.
- 노랑: 다음 봉 마감 대기 / 초록: 패턴 조건 충족.
- 빨강 `+`, 파랑 `−`: 가격 차이. 색상만으로 의미를 전달하지 않고 부호·문구도 함께 표시.
- 돌파선 가격 및 현재가 대비 차이 %.
- 돌파봉 종가 및 현재가 대비 차이 %.
- 진입 이격 구간: 종가 이하 / +0~3% / +3~5% / +5% 초과.
- 종가 +3%·+5% 비교 가격. **추천 매수가가 아닌 실험 구간 참고값**.
- 당일 등락률, 당일 고가, 고가 대비 현재가 차이 원/%.
- 당일 누적 거래대금과 돌파봉 추정 거래대금을 구분.
- 네이버 시세 시각, 장 상태, 출처, 돌파봉 시각, 패턴 데이터 기준 시각.
- 조회 상세 로그는 접어서 표시.
- 당일 고가 발생 시각은 확보하지 않아 돌파 전/후 고점인지 단정할 수 없다.
- 네이버 현재가·당일 고가·대금은 서로 다른 요청으로 받아 완전히 동시인 스냅샷이 아니다.

화면 일부 실행 안내에는 아직 ‘매수 검토’라는 표현이 남아 있다. 새 프로젝트에서는 **‘패턴 충족’으로 통일**하여 검증된 매수 추천으로 오해하지 않게 한다.

## 7. 기록과 장애 처리

코랩 실행마다 `pattern_snapshots/`에 저장:

- `*_universe.csv`: 그 실행에서 조회한 종목군·메타데이터.
- `*_scores.csv`: 전체 채점 결과·내부 단계별 통과 값.
- `*_top5.csv`: 최종 표와 후보 네이버 시세.
- `*_watch.csv`: 관찰표와 후보 네이버 시세.

코랩 런타임 초기화 시 파일이 없어질 수 있다. 현재는 사용자 다운로드가 필요하며 영구 저장·자동 백업은 구현되지 않았다.

시세 조회 실패는 해당 가격을 미제공으로 표시하고 패턴 결과를 유지한다. 기준값이 없을 때 0으로 대체하거나 과거 가격을 현재가로 위장하지 않는다.

## 8. 백테스트 방식과 용어

### 8.1 서로 다른 지표

- **+10% 도달률**: 정해진 관찰·청산 조건 안에서 목표가에 도달한 거래 비율.
- **수익 거래율**: 비용을 포함한 최종 손익이 양수인 거래 비율. +10% 도달률과 다름.
- **독립 신호 평균 수익**: 자금이 무한한 것처럼 각 신호를 별도로 계산. 실제 계좌 수익이 아님.
- **계좌 수익**: 보유·현금·중복 신호·정수 주식 수·재투자를 반영.
- **최대 낙폭**: 이번 구현에서는 시간봉 평가잔고 기준. 장중 최악의 낙폭보다 작게 측정될 수 있음.

### 8.2 공통 체결 가정

- 신호 계산에 완료봉만 사용하고 다음 관측 봉 시가 진입.
- 매수 후보 선정에 진입 봉의 최종 거래량·고가·저가를 사용하지 않는다.
- 선정 이후 거래량 0이면 체결 없음. 다른 종목으로 소급 대체하지 않음.
- 손절·익절 같은 봉 접촉은 손절 우선. 단, 시가에 이미 목표가 이상이면 목표 지정가 체결로 처리.
- 손절선 아래 갭은 시가 청산하여 손실이 -5%보다 커질 수 있음.
- +10% 익절, -5% 손절, 기본 최대 5거래일.
- 계좌형 비용은 편도 0.175% 가정. 실제 증권사 비용·세율을 검증한 값이 아님.
- 단일 포지션, 전액에 가까운 정수 주식 매수, 잔여 현금 보관.
- 같은 시각 최고 점수 선택. 보유 중 신호 무시, 청산한 봉에서 즉시 재진입하지 않음.
- 부분 익절 현금은 나머지 물량까지 청산하기 전 다른 종목에 투입하지 않음.
- 계좌형은 관찰 기간 끝 잔여 보유를 청산. 독립 신호형의 불완전 관찰 제외·평가손익 방식과 혼동하지 않음.
- 익절·손절을 장중 계속 감시한다는 가정. 사용자가 하루 3회만 매도까지 확인하는 상황을 재현한 것은 아님.

### 8.3 중요한 한계

**모든 고정 현재 종목군 연구에는 선택·생존편향이 있다.** 과거 날짜별 종목군과 상장폐지 종목을 완전히 복원하지 못했다. 단지 편향을 공지했다고 문제가 해결된 것은 아니다.

그 외:

- 반복해서 본 같은 기간은 새로운 검증 표본이 아니다.
- 시간봉으로 10:47 실제 진입, 체결 순서, 분봉 움직임을 정확히 복원할 수 없다.
- 15시 구간 누락은 손절/익절 순서와 잔고에도 영향을 준다.
- 거래대금 상위 종목을 현재 기준으로 고르는 것 자체가 과거 정보 누출 요소다.
- 주가 수정·기업행사·거래시장 차이 검증 미완료.
- 미체결·호가·유동성·정산·실제 거래비용은 완전 재현하지 않음.

## 9. 주요 실험 결과 요약

### 9.1 30거래일 독립 신호: 2026-08-03~09-14

| 조건 | 평가 건수 | +10% 도달률 | 비용 전 평균 수익 |
|---|---:|---:|---:|
| 기존 기본 패턴 | 687 | 40.9% | +1.98% |
| 돌파·거래대금 | 87 | 51.7% | +3.23% |
| 다음 봉 유지까지 확인 | 30 | 60.0% | +5.23% |
| 유지 확인 + 60분 지연 | 33 | 48.5% | +3.69% |

이 60%가 현재 운영 조건의 출발점이지만, **30건의 탐색 결과이며 안정적인 미래 확률이 아니다.** 같은 종목 반복과 겹치는 보유 기간이 존재한다.

이전에 검토한 전일 거래량 급증 가중치는 전체·이전 기간에서 개선되지 않아 미채택했다. 거래량 점수 비중·이격 제한의 소규모 탐색도 검증을 통과하지 못했다.

### 9.2 손절 전 상승·익절 전 하락

거래대금 동반 돌파 표본의 종목별 하루 첫 신호 분석:

- 손절 34건 중 청산 봉 이전에 +3% 도달 12건, +5% 4건, +7% 2건.
- +10% 도달 39건 중 먼저 -2% 이하 하락 22건, -3% 이하 하락 14건.

이는 손절폭을 무작정 좁히면 상승 거래도 놓칠 수 있음을 보여준다. 해당 숫자는 최종 유지 조건 30건과 다른 표본이다.

### 9.3 30일 계좌형: 매시간 신호를 받을 수 있다고 가정

초기 100만원, 비용 포함:

| 매도 방식 | 추가 지연 없음 | 60분 지연 |
|---|---:|---:|
| +10% 전량 익절 | 1,750,367원 | 2,005,310원 |
| +10% 절반 익절 후 추종 | 1,893,161원 | 2,125,711원 |
| 2거래일 정체 시 청산 | 1,576,264원 | 1,739,117원 |

실제 선택 거래는 9~12건뿐. 지연으로 성과가 좋아진 것은 거래 선택 경로가 달라진 영향이며 지연의 우월성을 뜻하지 않는다. 이 결과를 장기 기대수익으로 사용하지 않는다.

### 9.4 하루 09·12·15시 탐색

15시는 14~15시 봉 종가로 진입을 근사한 시나리오이며 실제 15시 이후 경로는 없다.

| 매도 방식 | 추가 지연 없음 | 60분 지연 |
|---|---:|---:|
| 고정 익절 | 1,115,962원 | 1,671,251원 |
| 부분 익절 후 추종 | 1,129,194원 | 1,687,763원 |
| 시간 청산 | 1,115,962원 | 1,415,472원 |

실행 시간을 제한하면 결과가 크게 바뀐다. 이 근사 실험만으로 최적 실행 시간을 추천하지 않는다.

### 9.5 진입 이격 제한

돌파봉 종가 +3% 이내 진입으로 제한:

- 지연 없음: 30건·60.0% → 24건·58.3%.
- 60분 지연: 33건·48.5% → 24건·50.0%.

기간별 개선이 일관되지 않아 자동 필터로 미채택. +3%/+5% 가격과 현재 이격 구간만 화면의 참고 정보로 추가했다.

### 9.6 연초 이후 11시 고정 검증

기간: 2026-01-01~09-16, 172거래일, 현재 고정 150종목.

- 12개 제한된 조합: 유지 확인/즉시 돌파 × 진입가 상한 없음/3%/5% × 60봉선 상승 확인 사용/미사용.
- 1~4월 학습, 5~6월 검증, 7월~9월16일 후속 확인.
- 추가 지연 0/60분, 진입가 시가/시가+0.3% 스트레스.
- 학습 기준: 각 시나리오 8거래 이상·시간봉 최대낙폭 20% 이내. **12개 모두 이 기준을 통과하지 못했다.**
- 따라서 아래 ‘개선 후보’는 학습 수익 기준의 탐색 후보이며 승인된 최적 전략이 아니다.

| 추가 지연 없는 전체 기간 | 기존 | 유지 확인 + 진입가 3% 이내 + 60봉선 상승 |
|---|---:|---:|
| 잔고 | 1,547,778원 | 1,830,463원 |
| 거래 | 44건 | 28건 |
| 수익 거래율 | 47.7% | 57.1% |
| +10% 도달률 | 40.9% | 46.4% |
| 최대 낙폭 | -33.3% | -29.5% |

후보는 5~6월 4거래 모두 목표 도달했으나 표본 부족. 60분 지연 검증에는 거래가 없었다. 7월 이후 수익 개선도 유지되지 않았다. **미채택, 코랩 조건 유지.**

### 9.7 상승 추세 눌림 재상승 연구

MA12>MA26>MA60 및 각 선 상승, 12/26선 눌림 후 재상승, 최근 거래대금 급증, 26선 이격 2 ATR 이내, 진입가 신호봉 종가+1% 이내를 고정 비교했다.

## 10. 새 프로젝트에서 먼저 해결할 일

### P0 — 성과를 과장하지 않는 재현 체계

1. 현재 운영 코드를 그대로 옮겨 실행 재현. 연구 함수가 운영에 섞이지 않게 한다.
2. 원본 데이터·조회 시각·종목군·설정·코드 버전·결과를 한 실행 단위로 묶어 보존.
3. 봉 시작 시각 / 봉 종료 시각 / 데이터 수신 시각 / 후보 발견 시각 / 시세 시각 / 실제 체결 시각을 별도 필드로 둔다.
4. 과거 종목군·상장폐지 포함 여부를 데이터셋 속성으로 기록. 미확보 시 편향 없는 검증이라고 표시하지 않는다.
5. 시세 제공 시장·수정주가·단위 불일치 검사. 차이가 크면 비교 신뢰도 미확인 표시.

### P1 — 실제 운용에 가까운 검증

1. 인증 없는 분봉 공급원을 조사하되, 이용 조건·보존 기간·지연·누락을 실측한 뒤 채택한다.
2. 과거 11시 직후 조회·판단 지연과 체결 가능한 가격을 복원할 수 있는지 확인.
3. 15:00~15:30 구간을 복구하거나, 누락 상태의 불확실성을 결과에 명시.
4. 매수 시각 고정과 매도 감시 방식(상시 주문/수동 확인)을 분리한 시뮬레이션.
5. +10% 도달률 외에 평균 손익, 손실 꼬리, 최대 낙폭, 평균 보유 시간, 기회비용, 무신호 일수 보고.
6. 새 기간에는 설정을 고정한 전진 검증을 우선한다. 결과를 보고 과거 조건을 반복 수정하지 않는다.

### P2 — 모바일 자동 운영(추가 구현 과제)

GitHub Actions는 논의만 되었고 아직 없다. 구축 시:

- 한국 장중 실행 시각과 스케줄 지연 가능성을 명시.
- 매 실행마다 전체 패턴 탐색, 필터된 후보만 현재가 보조 조회.
- 결과는 모바일에서 열 수 있는 정적 표/파일로 저장.
- 종목·신호봉 중복을 식별하고 새 후보와 재등장을 구분.
- 신호 발생과 사용자 실제 확인·매수 시각을 별도로 기록.
- 저장소 공개 범위·실제 거래 기록의 개인정보를 구분.
- 사용자 요청 없는 메시지 발송·알림 연동·계좌 주문 기능은 넣지 않는다.
- 기존 프로젝트의 Windows·C#·DB·오케스트레이터는 이식하지 않는다.

### 기능

- 코랩 단일 셀 실행, 다크테마 모바일 표, 차트 없음.
- 최종 패턴 최대 5개, 미달 종목으로 채우지 않음.
- 관찰표에는 다음 봉 마감만 대기하는 후보만 포함.
- 시세 실패·후보 없음·시장 휴장과 데이터 지연을 혼동하지 않음.
- 추가 시세 요청은 후보 코드별 중복 제거, 무후보면 0회.
- 표의 시각·가격 비교·단위가 정확하며 원본 자료로 추적 가능.
- 노트북 코드와 배포 Python 파일 일치.

### 백테스트

- 전체 데이터를 계산해 앞부분을 자른 결과와 해당 시점까지만 계산한 결과가 같아야 함(미래정보 불사용).
- 후보 선정에 진입 봉의 최종 거래량·고가·저가 금지.
- 동시 손절·익절, 갭, 정수 주식, 수수료, 부분 익절 잔금, 중복 보유 검증.
- 시작 현금 + 누적 실현손익 = 종료 현금(보유가 없을 때).
- 기간 경계를 넘는 학습 결과 누출 방지.
- 어떤 가격이 실측이고 어떤 가격이 근사·스트레스인지 구분.
- 거래 수 부족이면 ‘검증 부족’. 소수 거래의 100%를 확률로 표현하지 않음.
- 조건 변경은 독립된 후속 구간 검증 후 채택. 현재 결과는 대부분 반복 열람한 표본임을 유지.

### 투자 성과 목표의 취급

‘안정적인 +10%’는 사용자 목표이지 현재 달성한 기능이 아니다. 승률·낙폭·표본 수·실제 체결 조건에 대한 수용 기준을 사전 고정하고, 새 데이터에서 통과하기 전에는 검증 완료로 표시하지 않는다. 95% 수치 달성을 개발 완료 조건으로 설정하지 않는다.

## 14. 새 프로젝트 시작 시 전달할 핵심 지시

> 모바일 코랩 기반 한국 주식 60분봉 패턴 스캐너를 이어서 개발한다. 사용자는 안정적 우상향 후보를 찾아 약 +10% 수익을 얻는 것을 목표로 하지만, 현재 전략은 그 안정성이 검증되지 않았다. 최신 운영 코드는 다음 봉 유지 확인 전략이며, 후보만 네이버 시세를 보조 조회한다. 기본 패턴 미충족 종목은 숨기고, 다음 봉 마감 대기 후보만 별도 관찰표로 보여준다. 화면은 가벼운 다크테마 모바일 표, 주문은 사용자가 MTS에서 직접 한다. 공식 증권사 API·상시 개인 PC·차트는 요구하지 않는다. 기존 연구는 현재 고정 종목군, 15시 구간 누락, 과거 장중 실시간 가격 미확보, 반복 표본 분석의 한계가 있다. 좋은 과거 수익 숫자만 보고 새 설정을 활성화하지 말고, 원본 데이터와 체결 시점의 정합성·실제 운영 기록·새 기간 검증을 우선한다. 연구용 미채택 전략을 운영 코드에 섞지 않는다.
