# T-082 Mode2/상승초입 전진관찰 Action 안정화 및 누락 복구 체계 구축

## 1. 원인 분석 (GitHub Actions 로그 전수 검증, 2026-09-28 ~ 10-02)
1. **GitHub cron 지연 및 누락**: 17:40 KST 스케줄이 실제로는 00:00 KST 전후, 20:17 스케줄은 01:40 KST 전후에 생성됨. concurrency 대기로 다음날 11시~20시에야 시작된 실행도 발생하여 9/30분이 10/01 데이터로 봉인되면서 9/30 결측 발생.
2. **자정 이후 야후 자리표시 봉(MANIFEST_DATE_MISMATCH)**: 자정(KST) 이후 야후 파이낸스가 새 거래일의 빈 봉(OHLC 전부 NaN)을 붙임 → manifest의 `last`는 다음 거래일이 되고, 검증된 데이터의 `as_of`는 전일이 되어 날짜 불일치로 실패. (9/29, 9/30, 10/02)
3. **KRX 종목군 API 일시적 비JSON 반환**: `data.krx.co.kr`가 간헐적으로 비JSON 응답을 주며 `--refresh-universe` 단계에서 스크립트 중단. (10/01)

## 2. 해결 및 구현 내용
1. **야후 빈 봉 자동 제거 (`quant-research/scripts/fetch_daily_history.py`)**:
   - 데이터프레임 끝부분에 붙은 OHLC 전체 NaN 자리표시 봉을 제거하여 자정 이후 실행되더라도 `as_of`와 `manifest.last`가 완벽히 일치하도록 수정.
2. **KRX 장애 대응 Fallback (`quant-research/scripts/fetch_daily_history.py`)**:
   - 종목군 API 실패 시 직전 커밋된 universe 스냅샷으로 자동 폴백하고 manifest에 `universe_fallback`을 기록하여 파이프라인 중단 방지.
3. **스케줄 다중화 및 조기 종료 게이트 (`.github/workflows/early-inception-forward.yml`)**:
   - 평일 20:07, 21:07, 22:07, 23:07 KST 4회 스케줄 등록.
   - 첫 번째 성공 시 당일 봉인 파일(`$target.json`)이 생성되며, 이후 실행은 gate 단계에서 확인 후 데이터 수신 없이 5초 만에 정상 종료.
   - `workflow_dispatch`(수동 실행) 시에는 gate를 우회하여 즉시 실행 가능.
   - 일시적 네트워크 장애에 대비해 1회 실행 내에서 최대 3회 재시도(2분, 4분 지연).
4. **결측 거래일 자동 복구 체계 (Point-in-time Backfill)**:
   - `run_early_inception_forward.py`에 `backfill_missing()` 구현.
   - 스케줄 실패로 결측이 발생하더라도 다음날(또는 최대 5거래일 이내) 실행 시, 누락된 거래일의 시점으로 데이터를 엄격히 잘라(`loc[:cut]`) 횡단면 순위를 복원하고 봉인.
   - 복구된 봉인 파일에는 `backfill` 메타데이터(복구 원본 일자, 기준 universe 일자, 사후 복구 명시)를 기록하여 원칙 유지.
   - 결측 복구 시에도 GitHub Actions가 raw 데이터를 보존하고 커밋하도록 워크플로 연동.
