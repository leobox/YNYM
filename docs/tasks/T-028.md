- 2026-09-18: 원인 분석 — commit 로그 확인 결과 09-18 10:41~14:13 사이 자동 커밋이 하나도 없었고,
  이 구간이 사용자가 collector.py를 수동으로 계속 커밋/푸시하던 시간대와 정확히 겹침.
  `collector.yml`의 마지막 push 단계가 pull/rebase 없이 바로 `git push`만 해서, 워크플로우
  체크아웃 이후 사용자가 먼저 push하면 non-fast-forward로 거부되어 그 회차가 조용히 실패하는
  구조였음 (350종목 유니버스나 1분20초 스캔 시간 자체는 원인이 아니었음 — 별도로 사용자에게
  확인·공유함).
- 2026-09-18: 조치
  1. `check-holiday` job 추가 — `holidays.KR()`로 KST 기준 오늘이 한국 공휴일이면
     `should_run=false`를 출력하고 `run-collector` job을 skip. `workflow_dispatch`(수동 실행)는
     항상 통과시켜 사용자가 공휴일에도 수동 테스트는 계속 할 수 있게 함.
  2. push 단계를 `git pull --rebase origin main && git push` 후 실패 시 최대 5회, 점증 대기
     (5s/10s/.../25s)로 재시도하도록 수정. 강제 push는 사용하지 않음.
  3. `python -m yaml` 로 워크플로우를 파싱해 `run:` 블록이 YAML 들여쓰기 스트립 후 올바른
     bash/heredoc/python 문법이 되는지 직접 검증함(로컬 python.exe 직접 실행 시엔 오탐 발생 —
     YAML 파서를 통과시켜야 정확함).
- 완료 근거: `holidays` 패키지는 `check-holiday` job 내부에서만 설치(collector 런타임
  requirements.txt에는 추가하지 않음 — collector.py 자체는 공휴일 판단을 하지 않으므로).
