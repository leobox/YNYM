# T-003: 퀀트 연구: 기본 데이터 수집 및 백테스팅 프레임워크 설계

## 📋 요약
yfinance/pandas를 활용한 과거 시세 수집 헬퍼 및 미래 참조 편향(Lookahead Bias)이 차단된 백테스트 기본 구조를 작성한다.

## 📝 실제 구현 및 범위 조정
- **데이터 수집 헬퍼**: `scanner/data_adapter.py`(`fetch_universe`, `get_json` 재시도/타임아웃 포함)가 이미 KRX 종목군 대상으로 이 역할을 하고 있어 별도 구현하지 않음. 원 요구사항의 "yfinance"는 미국 티커 중심 라이브러리라 이 프로젝트의 KRX 60분봉 대상과 맞지 않아, 기존 Naver/FinanceDataReader 기반 어댑터를 그대로 채택하는 것으로 범위를 조정함 (AGENTS.md 3항: 규칙-요구 충돌 시 근거 기록).
- **백테스트 기본 구조(본 작업의 핵심)**: `research/walk_forward.py`의 `WalkForwardTest`가 이전에는 스텁(`run()`이 하드코딩된 워닝만 반환, `signal_func`/`account_func`를 실제로 호출하지 않음)이었음. 이번에 실제 동작하는 구현으로 교체:
  - 생성 시점에 train/validate/test 구간의 세션 중복을 검사해 겹치면 `ValueError` — 구간 경계를 넘는 데이터 유출을 원천 차단.
  - `run(signal_func, account_func, data, names)`는 각 구간에 대해 `signal_func(data, names, sessions)` → `account_func(entries, data, sessions)`를 실제로 호출. 어댑터 계약은 기존 `research.signal_generator.generate_signals` / `research.account_simulator.simulate_account`의 첫 3개 위치 인자와 일치 (`functools.partial`로 나머지 kwarg 바인딩).
  - 신호 0건인 구간은 계좌 시뮬레이터를 호출하지 않고 `closed_trades: 0`으로 처리 (AGENTS.md 4항: 후보 0개 허용). `generate_signals`가 빈 rows에서 컬럼 없는 DataFrame을 반환하면 `simulate_account`의 `entries.groupby('scan')`이 `KeyError: 'scan'`을 던지는 기존 상호작용 버그를 우회.
  - 동일 인스턴스에서 `run()`을 재호출해 이미 소비한 세션이 재등장하면 `research.bias_reporter.get_bias_warnings(repeated_samples=True)`로 경고 — "반복 열람 기간을 새 OOS로 취급하지 않는다"는 규칙을 실제로 반영.
  - `aggregate`는 구간별 `closed_trades` 합계만 제공하고 CAGR/Sharpe 등은 만들지 않음 (표본이 짧은 구간에서 허위 정밀도를 만들지 않기 위함, `quant-backtest-validator` 스킬 가이드 준수).
- **테스트**: `tests/test_walk_forward.py` 5건 추가 — 구간 중복 거부/허용, 3구간 독립 실행, 재실행 시 반복 샘플 경고, 빈 구간(0세션) 처리. `pytest tests/` 전체 52건 통과, `python tools/ai/quant_guard.py` 36개 소스 통과.

## 🚧 남은 한계 (미검증)
- 실제 시장 데이터(네트워크)로는 검증하지 않음 — 합성 픽스처(`conftest.py`)만 사용. 전략 유효성이나 +10% 도달률은 이 작업의 범위가 아니며 여전히 미검증.
- `generate_signals`/`simulate_account`의 빈 DataFrame 상호작용 버그는 `walk_forward.py`에서만 우회했고 두 함수 자체는 수정하지 않음 — 다른 호출부에서 같은 패턴으로 빈 신호를 넘기면 여전히 재현 가능.
- `aggregate`는 단순 합계이며 구간 간 자본 곡선을 잇지 않음 — 포트폴리오 전체 성과가 필요하면 별도 설계 필요.
