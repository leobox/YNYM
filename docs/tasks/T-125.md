# T-125 — 신호 등록 피처 정합성(Top5/Watch) 및 등록 이후 시점 라벨링(`tracker.py`) 교정

## 1. 배경 및 문제 정의 (T-120 감사 후속)
`T-120` 2차 정합성 감사에서 확인된 두 가지 구조적 결함을 교정한다.

1. **`Watch` 후보의 `_features` 1봉 밀림(Shift) 및 신호 단계 미구분 (`collector.py`)**:
   - `confirmed_breakout()`에서 `trigger_amount`, `trigger_ratio`, `breakout_level`은 `shift(1)`된 직전 봉 기준 지표이며, `current_amount`, `current_ratio`, `current_level`이 현재 마감봉(`iloc[-1]`)의 돌파 지표이다.
   - `Top 5` 확정(`conf.hold == True`) 종목은 직전 봉(`iloc[-2]`)이 돌파봉이고 현재 봉(`iloc[-1]`)이 안착 확인봉이므로 `trigger_*`가 맞지만, `Watch` 대기(`conf.waiting == True` & `not _match`) 종목은 **현재 봉(`iloc[-1]`) 자체가 돌파 발생봉**이다.
   - 기존 `score_stock()` 및 `build_results()`는 `Watch` 종목에도 `shift(1)`된 `trigger_*`와 `c.iloc[-2]`를 그대로 `_features`에 기록하여, `Watch` 테이블 표시값(`_current_*`)과 `pending_signals.json` / `resolved_signals.jsonl`의 `features` 간 수치 불일치가 발생했다.
2. **신호 등록 시각(`registered_at_kst`) 이전 분봉을 청산 판정에 사용하는 시간 역전 (`tracker.py`)**:
   - `SignalTracker.update_with_bars()`가 `c["time_kst"] > sig_time` 조건만으로 5분봉을 필터링하여, 예를 들어 `signal_time_kst = "2026-09-18 09:00"` 신호가 `"2026-09-18 10:41:46"`에 등록된 경우 `09:05 ~ 10:40` 구간의 과거 5분봉으로 등록 이전 시점에 조기 손절/익절(`exit_time = 09:05` 등)이 확정되는 문제가 있었다.

## 2. 주요 변경 사항

### A. `quant-collector/collector.py`
- `score_stock()` 및 `build_results()`에서 신호 단계(`signal_stage`)를 명시적으로 기록:
  - `Top 5` 조기 돌파: `"signal_stage": "top5_early"`
  - `Top 5` 60분봉 확정 돌파: `"signal_stage": "top5_hold"`
  - `Watch` 다음 봉 지지 대기: `"signal_stage": "watch"`
- `Watch` 행(`_waiting == True` and `not _match`)의 `_features`를 현재 돌파봉 지표와 일치하도록 정렬:
  - `trigger_amount_e8 = float(r["_current_amount"])`
  - `trigger_ratio = float(r["_current_ratio"])`
  - `breakout_level = float(r["_current_level"])`
  - `trigger_close = float(r["_current_close"])`
  - `current_close = float(r["_current_close"])`

### B. `quant-collector/tracker.py`
- `SignalTracker.register_signal()`에 선택적 `registered_at_kst: Optional[str] = None` 인자를 추가하여 테스트 및 명시적 등록 시각 주입을 지원.
- `SignalTracker.update_with_bars()`에서 실질 평가 시작 기준 시각(`cutoff_time`)을 `max(sig_time_norm, registered_at_kst[:16])`로 계산(동일 일자 등록이거나 신호일 이후 7일 이내 유효 등록 시각인 경우 적용)하고 `sig["effective_eval_start_kst"] = cutoff_time`에 기록.
- `future_bars = [c for c in candles if c["time_kst"] > cutoff_time]`으로 필터링하여 등록 시각 이전에 형성된 분봉에서 선행 청산 판정이 일어나지 않도록 차단.
