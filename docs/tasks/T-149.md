### RR3 — P1: 사전 봉인 핸들을 재사용하면 기존 실행 결과를 덮어쓰고 다른 설정까지 연결함

- **위치**: `quant-research/research/sector_v1/evaluator.py:1951`, `:1982`, `:2028`, `:2077`.
- **연관**: T-148 R3, 사양 §§8–10의 불변 원장·실행 전 봉인·시도 구분.
- **입력/행동**: `seal_pre_run_attempt()`로 seed20261107 실행1을 봉인한다. 정상 결과를 저장한 뒤 실제 평가를 seed7로 다시 실행하고, 동일 `pre_sealed_run` 핸들로 `seal_and_register_evaluation_run()`을 호출한다.
- **실측**: 예외 없이 같은 폴더의 첫 보고서가 덮어써진다. 등록부에는 `attempt_number=[1,1]`이 생기고, 두 항목이 서로 다른 report 해시를 같은 경로에 연결한다. 디스크 사전 봉인 seed는 **20261107**, 저장된 새 보고서의 seed는 **7**이다.
- **영향**: 재시도/잘못된 핸들 재사용만으로 완료 실행의 원장을 파괴한다. 입력·코드·설정 해시가 다른 보고서를 다른 사전 봉인에 연결할 수도 있다. 원장 파일을 추가한 수정은 유효하지만 불변성과 봉인 연결이 아직 보장되지 않는다.
- **기대 수정**: 어떤 파일도 쓰기 전에 핸들·디스크 사전 봉인·보고서의 봉인 핵심 해시와 실행 설정을 대조한다. 이미 완료된 실행은 다른 내용이면 거부하고, 같은 내용의 재시도는 기존 결과 반환 또는 명시적 거부로 처리한다. 새로운 결과는 새 시도 번호가 필요하다. 저장 도중 실패에도 완료된 원본이 바뀌지 않도록 임시 산출물/완료 표식을 사용한다.
- **재검증 조건**: 같은 핸들로 두 번째 결과를 저장하려 하면 거부되고 첫 실행의 모든 파일 해시가 유지돼야 한다. 완료 전이라도 다른 seed/입력/비용 보고서는 연결할 수 없어야 한다. 동일 결과 재시도 때문에 시도 번호가 중복돼서는 안 된다.

### RR1 — P1: 희소 달력을 완전한 달력으로 인정해 실제 거래일 210개를 건너뛰어도 24개월 조건 통과

- **위치**: `quant-research/research/sector_v1/models.py:204`, `:257`, `:271`, `:299`; 실행기 `execution_e0.py:383` 부근의 `calendar.sessions_in_range()`.
- **연관**: T-148 R4, 사양 §§3,7,9의 매일 완료 종가 판정·거래일 지연·20거래일 통계.
- **입력**: 합성 기준 달력/벤치마크에는 **2024-01-01~2026-01-05의 평일 526개**에 완료 바가 있다. 실행 달력에서는 모든 화요일·목요일을 삭제해 월·수·금 **316개**만 제공한다. 이것은 한국 실제 휴장일 주장이나 공식 달력 데이터가 아니라 누락 검출용 합성 입력이다.
- **실측**: 관측 바가 존재하는 **210개 세션 누락**에도 `calendar_complete_for_requested_window=True`, `meets_24_months=True`, `max_benchmark_missing_ratio=0.0`이다.
- **원인**: 월10개 이상·최대 내부 간격14일·가장자리7일 이하라는 휴리스틱을 달력 완전성으로 승격한다. 자료 수신율도 주어진 희소 달력 안의 날짜만 분모로 쓰므로 누락된 거래일을 발견하지 못한다.
- **영향**: 앞뒤가 잘린 50일 달력 문제는 수정됐지만, 중간 거래일이 빠진 입력은 여전히 정상 검증으로 표시된다. 시뮬레이터가 빠진 날의 청산 판정을 생략하고 예정 실행/지연 기준도 달라지며, 계좌 수익의 20행 블록이 20거래일을 뜻하지 않게 된다.
- **기대 수정**: 봉인된 달력의 출처·유효 구간·예정 세션 목록을 검증하고 가격 자료와 양방향 대조한다. 벤치마크 거래일이 달력에 빠졌다면 공급원 날짜/시장 오류와 구분해 해소하기 전 검증 부족으로 처리한다. 월별 건수 휴리스틱은 이상 탐지용으로만 사용하고 완전성 증거로 사용하지 않는다. 승인된 휴장·주말에는 바가 없어도 정상이라는 반례도 유지한다.
- **재검증 조건**: 위 210개 누락은 명시적 오류/검증 부족이어야 하며, 공식 예정 세션에 대한 일부 가격 누락과 달력 자체 누락을 구분해 기록해야 한다.

### RR2 — P2: 저장한 E1 규칙 위반이 기본 재로딩 경로에서 정상 준수로 바뀜

- **위치**: `quant-research/research/sector_v1/journal_e1.py:344`, `:545`, `:602`, `:642`.
- **연관**: T-148 R6, 사양 §6의 실제 확인 기록·규칙 위반 보존.
- **입력**: 신호일 금요일 **2026-03-06**, 정상 다음 세션 월요일 **03-09**인 합성 달력에서, 예정 확인일과 실제 체결일 모두 **03-10**인 진입을 달력과 함께 저장한다.
- **실측**: 저장된 JSONL에는 `PROTOCOL_VIOLATION_PRESERVED`와 `ENTRY_CHECK_SESSION_LATER_THAN_NEXT_TRADING_SESSION`이 있다. 달력을 전달해 읽고 요약하면 정상 진입0건이다. 공개 함수의 기본 호출 `summarize_e1_journal(load_e1_journal(path))`는 **정상 진입1건 / 위반0건**으로 바꾼다.
- **원인**: 로더가 저장된 `compliance_status`와 `protocol_violations`를 버린다. 달력 인자가 기본값 None이면 다음 세션 검사를 생략하고 COMPLIANT를 반환한다. 같은 날짜 확인·주문·체결이라 일반 지연 검사로도 복원되지 않는다.
- **영향**: 파일에 보존됐던 실행 위반이 보고서에서 정상 기록으로 집계된다. 현재 수익성 주장 플래그는 항상 False여서 이 재현이 수익성 승인으로 이어지지는 않지만, 준수 거래/에피소드 집계는 오염된다.
- **기대 수정**: 저널에 검증 달력/버전을 연결하여 읽을 때 복원하거나, 필요한 달력이 없으면 준수 여부를 UNKNOWN/UNVERIFIED로 표시한다. 저장된 위반 근거를 유지하며 최신 재평가 결과와 구분한다. 달력을 생략했다고 위반을 정상으로 승격하지 않는다.
- **재검증 조건**: 위 기록은 기본 로딩에서도 정상 진입으로 세지 않아야 한다. 다른 달력으로 재평가할 때도 이전 판정과 근거는 감사 가능하게 남겨야 한다.
