`D:\RUNG'S GYM`(이 저장소 밖의 실제 사용 중인 프로젝트)에 이미 완성·배포된 앱이 존재함을 확인:
- `RungsGym`(v1.0, 패키지 `com.rungsgym.app`) — 더 단순한 초기 버전
- `TimeFitness`(v1.0~1.5, 패키지 `com.timefitness.app`) — 캘린더 기반, Playwright 화면 테스트 보유, 더 성숙

사용자가 **TimeFitness를 gym-app으로 이전**하는 방향을 선택함(RungsGym은 이전하지 않고 참고만).
따라서 "Kotlin+Compose+Room으로 새로 설계"라는 원래 계획은 폐기하고, 실제 동작하는
WebView 셸 + 단일 HTML/JS + `SharedPreferences` JSON 저장 구조를 그대로 가져와 이 저장소에 정착시켰다.

## 🔍 실제 아키텍처 (원래 backlog 문구의 "Room 스키마"와 다름)
- 저장: Room/SQLite가 아니라 `SharedPreferences`에 JSON 한 덩어리 (JS ↔ `MainActivity.java`의 `Native.save/load` 브리지).
- UI: `assets/index.html` + `assets/app.js` + `assets/data.js` 단일 페이지, WebView로 표시.
- 빌드: Gradle/Android Studio 없이 `time-fitness/build.py` (Java `javac`/`d8` + 포터블 Android SDK의 `aapt`/`zipalign`/`apksigner`).
- 테스트: 실기기/에뮬레이터가 아니라 Playwright + headless Chromium으로 `assets/index.html`을 직접 구동 (`test-1.5.cjs`).

- `D:\RUNG'S GYM\time-fitness`의 소스(assets/java/res/AndroidManifest/build.py/test-*.cjs)를 `gym-app/time-fitness/`로 복사.

## ✅ 검증 (실제로 빌드·서명·화면 테스트까지 수행)
- 로컬 검증용으로 `gym-app/tools/android-sdk`를 기존 `D:\RUNG'S GYM\tools\android-sdk`에 대한 **디렉터리 정션**으로 연결(복사 아님, git 미추적) 후 `python time-fitness/build.py` 실행 → 성공, `TimeFitness-1.5.apk` 생성.
- `apksigner verify`로 재빌드한 APK와 원본 `D:\RUNG'S GYM\TimeFitness-1.5.apk`의 서명 인증서 SHA-256이 **완전히 일치**함을 확인(`a741cea7...`) — 마이그레이션이 실제로 원본과 동일한 서명 체인을 재현함을 증명.
- `npm install` (playwright-core, devDependency로 `package.json` 추가) 후 `npm test`(`node test-1.5.cjs`) 실행 → 전체 PASS (메모/캘린더/백업·복원/폴드 레이아웃/JS 에러 없음 등 전항목).
- `python tools/ai/quant_guard.py`는 이 프로젝트를 대상으로 하지 않으므로 영향 없음 확인.
