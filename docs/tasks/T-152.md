## P1 — setuptools 한 건 또는 lock만 수정하면 환경 경고가 남음

`requirements-lock.txt:66` 및 설치 환경 모두 `setuptools==78.1.0`이었다. CVE-2025-47273은 78.1.1에서 수정되지만, 이후 Windows legacy wheel 경로 이탈 권고 GHSA-xmj3-9gf7-h52w의 수정 버전은 84.1.0이다. 78.1.1만 적용하고 전체 해결로 보고하면 안 된다. 실제 악용은 취약 설치 경로와 공격자 제어 wheel 등 조건에 의존하며, 이 검토에서는 악성 입력을 실행하지 않았다.

| 패키지 | 검사 버전 | 감사 DB가 제시한 수정 버전 중 최댓값 | 고유 경고 ID 수 |
|---|---|---|---|
| certifi | 2026.7.22 | 2026.10.18 | 1 |
| filelock | 3.32.3 | 4.2.1 | 12 |
| pillow | 12.3.0 | 13.0.0 | 42 |
| setuptools | 78.1.0 | 84.1.0 | 3 |
| soupsieve | 2.9.2 | 4.0.0 | 4 |
| tornado | 6.5.10 | 6.6.1 | 4 |
| transformers (환경에만 있음) | 5.5.4 | 5.10.0 (1건), 수정 버전 미지정 (1건) | 2 |

표는 자동 업그레이드 승인이나 호환성 보장이 아니다. 특히 transformers의 CVE-2026-9856은 5.10.0이 수정 버전이나, CVE-2026-80047은 조회한 권고에서 patched version이 None이다. 후자는 custom generation code를 동의 확인 전에 캐시에 다운로드하는 문제이며, 즉시 코드 실행과는 구분된다. 업그레이드 후 재감사하고 잔여 항목의 실제 호출 경로와 완화 조치를 확인해야 한다.

## P1 — setup.ps1로 복구하면 이미지 생성 패키지 35개 제거

`setup.ps1:11`의 `uv pip sync`를 동일 인자로 `--dry-run` 실행한 결과 `Would uninstall 35 packages`를 확인했다. 실제 삭제는 하지 않았다. `optimum-intel`, `diffusers`, `transformers`, `openvino-genai` 등이 대상이다. 예를 들어 `generate_meinamix.py:9`, `run_img2img.py:12`는 `optimum.intel`을 import하므로 복구 후 실행이 깨질 수 있다.

T-153에서 보안 패치와 함께 기존 이미지 생성 의존성의 보존 방법을 확인할 것. 전체 118개를 무조건 freeze하기보다는 현재 사용 기능의 의존성을 반영하거나 기본 GPU/이미지 생성 환경을 명시적으로 분리해야 한다. lock 6개 패키지 검사만으로 실제 환경 전체의 취약점 제거를 주장하지 않는다.
