## 📌 항목별 요약

- **시장 상황:** 완료 일봉의 시장 폭(SMA60)과 최근 5거래일 추이, 그리고 상승초입 단계별 게이트 생존 종목 수를 함께 표시합니다. 시장 폭이 40% 미만이면 두 일봉 전략의 후보 선별을 중단(`🔴 후보 선별 중단`)하며, 40% 이상이더라도 최근 5거래일 고점·초기 대비 `-5.0%p` 이상 하락하거나 3거래일 연속 하락 중이면 `🟡 레짐 둔화 주의`를 표시합니다(선별 조건 자체는 변경하지 않음).
- **게이트별 생존:** 감시 유니버스(유효 종목) 중 `추세·대금(SMA20·60 및 5억)` → `비과열(60일 모멘텀 ≤25%, SMA60 이격 ≤1.18)` → `20일 수축(변동폭 ≤25%, 수축비 ≤0.85)` → `최종 통과(돌파 확정 / 수축 돌파임박)` 단계별 통과 종목 수입니다. 최종 후보가 `0건`인 날에도 수축 베이스 종목이 마른 휴식기인지, 돌파 대기 종목이 축적되는 중인지 확인할 수 있습니다.

## 🔎 최종 상승 초입 관찰 가이드 (`T-131` · `T-133`)

3개년·1개년·2026년 YTD 백필 비교 결과, 거래량 5배 급등을 추격하던 기존 `상승초입 3일 이내`는 손절률이 높고 기대수익률·손익비가 가장 낮아 **폐기**했습니다. 대신 메인 화면은 수동 MTS 및 연금계좌 운용 시 즉시 참고할 수 있도록 **① 주식 최종 상승 초입**과 **② ETF 상승 초입 (연금계좌 매수 가능)** 두 섹션으로 구성했습니다.

1. **상승 초입 · 20일 돌파 확정 (`early_inception` / ETF `breakout`)**
   - **조건:** 추세·대금(`Close ≥ SMA20`, `SMA20/60 정배열`, 20일 거래대금 중앙값 `≥ 5억`) + 비과열(`60일 모멘텀 ≤ 25%`, `SMA60 이격 ≤ 1.18`) + 20일 변동성 수축(`변동폭 ≤ 25%`, `수축비 ≤ 0.85`) + **직전 20일 고점 종가 돌파(`Close ≥ prior_h20`)** + 수급 점화(`5일 거래량비 ≥ 1.20x` 또는 `당일 ≥ 1.35x`, `CMF20 ≥ -0.05`).
   - **특징:** 20일 박스권 상단을 이미 종가로 돌파한 정석 후보로, 단기(5거래일 내) `+5%` 도달 탄력이 가장 빠릅니다.
2. **상승 초입 · 20일 수축 돌파임박 (`early_contraction` / ETF `watch`)**
   - **조건:** 동일한 추세·대금·비과열·수급 점화 조건 위에서 20일 변동성 수축과 거래량 점화를 충족한 채 **직전 20일 고점 아래(개별주는 `수축비 ≤ 0.65` 및 고점 `-3.0%` 이내)**에서 돌파를 준비 중인 길목 후보입니다.
   - **특징:** 돌파 확정 표에 종목이 뜨지 않는 지수 눌림·숨고르기 구간에서도 선제적 거래량이 유입된 길목 종목·ETF를 포착하며, 개별주 다기간 백필에서 기대수익률·손익비가 가장 높고 `-5%` 손절 도달률이 가장 낮았습니다.
3. **MTS 및 연금계좌 참조 가격선 안내**
   - **20일 기준고점 (돌파이격):** 직전 20거래일 최고가(돌파 기준선)와 현재 종가의 괴리율입니다.
   - **참조 손절 / 추세선:** 평가일 종가 대비 `-5%` 보호 손절 기준가 및 단기 추세 약화 기준선인 `SMA10`(10일 이동평균선)입니다.
   - 다음 날 시초가 갭이나 장중 체결 여부는 일봉 관찰에 반영되지 않으며, 전진 관찰의 가상 성과 평가는 20거래일 확보 후 추세 약화 청산 엔진(`SMA10` 이탈·고점 대비 `-6%` 트레일링·`-5%` 손절)으로 독립 집계됩니다.

가격 이력과 EPS 캐시는 각 로컬 데이터 원본이 필요합니다. T-096의 준비 상태 명령으로 매번 최신 일봉의 신선도를 확인하세요. GitHub Actions의 일봉 패널은 별도의 공개 시세 수신 결과를 사용하며 EPS 캐시나 SUE 점수를 사용하지 않습니다.

## 📋 백로그 관리 (CLI 기반 SSOT)

`backlog.json`은 직접 수정하지 않고 반드시 CLI 도구를 사용합니다:

```bash
# 1. 지금 바로 착수 가능한 작업 확인
node tools/backlog.mjs next

# 2. 작업 착수 (코드 수정 전 필수!)
node tools/backlog.mjs set <id> in_progress

# 3. 작업 완료 처리
node tools/backlog.mjs set <id> done

# 4. 판단/대기 상태 기록 (사유 필수)
node tools/backlog.mjs set <id> needs_decision --note "결정 필요 사유"

# 5. 작업 통계 및 무결성 검증
node tools/backlog.mjs stats
node tools/backlog.mjs check
```
